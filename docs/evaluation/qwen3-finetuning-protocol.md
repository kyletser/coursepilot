# Qwen3-4B 微调实验协议

日期：2026-09-11。状态：实验已完成；最终结论见 `qwen3-final-report.md`。
用户最终明确：微调不要求优于原模型，真实训练、技术取舍和可追问的证据即可。
以下保留执行前协议与补充验证记录；不再为了正向提升继续训练。

目标是实际训练模型、改善 CoursePilot 可信问答，并产生可用于简历的可复现对照结果。不能用模板训练集上的分数、降低评测门槛或仅降低 loss 代替最终效果。

## 数据与实验

1. 先修复引用评测忽略不匹配引用的问题，按每个生成 Claim–Citation 配对统计，错误引用不能增加覆盖率。保留历史报告，新口径单独标版本。
2. 为无可回答证据定义合法 `{"claims": []}`，核心流程返回已有拒答状态；该机制同时用于原模型和微调模型，单独记录工程改动，避免把工程改动收益全归因于微调。
3. 原创课程风格行为数据按资料/概念分组划分 train/dev/test。包含有依据回答、多个证据、干扰资料、否定与条件、错误预设和资料不足。明确标为 AI 辅助构造，不声称人工教师盲标。
4. 已有 360 条内部冻结用例不用于训练；外部公开数据若引入，固定来源、许可证和选择规则。测试问题与答案不用于 checkpoint 选择。
5. 先冻结数据文件与 SHA256，再运行原模型基线和训练；只用开发集选模型。最终测试如暴露问题，要保留结果，新增开发数据后使用新的未调参测试版本确认。
6. 同时记录原始模型输出与经过 Agent 防护后的输出，避免摘要降级掩盖模型生成失败。

## 指标及验收证据

- 原始输出：JSON/Schema 成功率、引用编号合法率、全部输出引用的来源支持代理指标、答案覆盖/文本匹配、不可回答拒答率与可回答误拒答率；逐项保留分子分母。
- 系统效果：真实 TrustedAgentCore 调用的回答、拒答、摘要降级、生成次数、延迟分布；另行运行实际检索 QA 回归，不以给定证据实验替代全链路。
- 延迟：预热后相同输入、相同输出预算；报告 P50/P95、输出 Token、生成速度、峰值 GPU 显存。单并发不能包装成高并发。
- 训练：数据哈希、Git 提交、基础模型 revision、LoRA 配置、优化器、学习率、批次、梯度累计、长度、seed、loss、耗时、依赖版本、checkpoint 文件哈希。
- 必须实际生成可加载的适配器，并验证其接入 CoursePilot 的模型适配器；对生成失败或拒答的行为保留回归测试。
- 最终材料：训练与推理脚本、数据构造与划分说明、原始基线/微调报告、改进和退化案例、简历事实版本及面试取舍说明。

不预填任何提升数字。引用词法匹配只能称代理评测，不称严格语义蕴含。若没有观察到可靠增益，报告负结果并继续在开发集定位，不调整测试标签迎合模型。

## 多技术方案比较边界（2026-09-11 更新）

用户目标补充为“选择不同的技术方案”。采用分层比较，不把模型、检索、
提示词和部署后端同时更换后产生的差异全部归因于微调：

| 层次 | 对照方案 | 用途与证据边界 |
|---|---|---|
| 检索 | Dense-only / Hybrid + Reranker | 复用已有冻结检索实验；不能与新微调数据混算提升率 |
| 生成 | 相同提示词下原始 Qwen3-4B / QLoRA 适配器 | 相同量化、证据、解码、预算，隔离参数微调收益 |
| 安全治理 | 同一调用的原始结构化输出 / TrustedAgentCore 最终响应 | 区分模型生成、拒答与摘要降级；属于配对诊断，不是取消权限的线上实验 |
| 数据工程 | v1 短证据训练 / v2 长证据与条件保持训练 | 旧测试已被观察，只作回归；v2 新测试在候选固定后一次运行 |
| 部署 | Ollama 本地演示 / Transformers + PEFT 远端适配器 | 展示部署和回滚路径；未在同一硬件同精度比较前，不声称后端性能优劣 |

全参数 SFT、BF16 LoRA、DPO 目前仅是备选方案，不写成已完成实验。
本轮先用 QLoRA 控制单卡显存和训练范围；是否增加第二种训练算法，应由
当前失败类型和数据条件决定，而不是为了堆叠名称。DPO 需要可信的偏好对，
现有结构化监督样本并不自动满足这一条件。

外部 50 条迁移测试额外加入原模型 two-shot 对照，在任何外部输出出现前固定：
从 v2 训练集中分别选择 `single_evidence` 和 `missing_evidence` 最小 ID，即
`v2-original-train-0000`、`v2-original-train-0006`。保留完整示例证据与答案，
压缩掉无关元数据，753 字符的提示后缀 SHA256 为
`5eb1b916df797d332e53a0e5effb7d9e81f965c253b733484d1996b475bb838a`。
只追加格式示例到系统提示，当前用户证据、引用白名单和反馈不变。
该对照增加上下文成本，不声称与零样例提示的输入 Token 相同；报告实际用量。
三个方案按用例轮换运行顺序。此项不改已经运行的新合成测试提示，也不改默认系统。

第二轮发布门槛在读取新测试结果前明确：新给定证据测试同时报告正负例、
原始与防护后结果；原 80 条课程 QA 的误拒答不能高于配对原模型，不可回答
拒答不能退化；独立 CMRC 50 条的生成答案与摘要降级分开统计。任何质量收益
必须同时披露延迟代价和代理指标局限。若不同测试结论冲突，不默认推广适配器，
保留原模型与完整负结果。通过这些门槛也不等于已证明全部答案的语义正确性。

### 外部原文匹配偏差与独立补充验证

首次 50 条外部三方案实验完成后，原模型 / two-shot / QLoRA 的最终生成
原文片段命中为 20/50、23/50、39/50。逐例查看全部 19 条 QLoRA 配对改善发现，
大部分基线是正确转述，分数差异主要反映抽取风格，**不能作为语义准确率提升**。
保留原评分和输出，不修改这些测试的 gold；也不再用其大幅差值证明跨域效果。

为区分事实覆盖与复制风格，新增 `cmrc-contrast-v2`，同一固定模型、同一
two-shot 示例，不再训练或修改提示。排除原检索前 50 个上下文以及首次生成集
中的全部证据上下文，从剩余资料按 context_id、query_id 选 50 个问题（参考
答案规范化长度 2–12），每个搭配有证据/缺失证据两种输入，共 100 条。
`cmrc-contrast-v1` 只是生成前的草案，没有调用模型、没有结果。

正式补充数据 SHA256：
`1de33d7b552a9d1be3045c913d072f5ccc673648b874202165f3eac91a5be0c6`。
脚本 `build_external_contrast.py` 与 `cmrc_contrast_answer_keys.json` 固化全部
选择和必要答案字段。答案键由 AI 根据原官方参考答案在任何新模型输出前审核，
不是独立人工复核；多字段使用 AND、别名使用 OR，数字避免匹配更大数字的子串。
别名集仍可能遗漏正确转述，因此不宣称完整语义评分。

正例要求最终 ANSWERED，且带正确来源的 Claim 覆盖全部预声明答案字段；
负例要求 INSUFFICIENT_EVIDENCE。原始输出与系统输出分别记录，摘要降级不算
模型回答正确。缺证据例为替换成无答案键的无关段落，不是 CMRC 官方不可回答
标注，也不等同自然难负例。原始公开资料是否进入基础模型预训练未知。
这次补充不是修改旧口径后重打同一测试，而是独立资料上的新验证；执行后不改
字段、别名或病例。报告同时呈现三个方案的正负例和延迟，不只呈现最高分。

## 环境排障记录

服务器 Ubuntu 20.04 的 glibc 不满足 bitsandbytes 0.45.5 自带 CUDA 12.6
二进制的 GLIBC_2.34 要求；PyTorch CUDA 张量运算本身通过。服务器已有 CUDA
12.4，且该包的 cuda124 动态库依赖检查通过，因此仅给实验进程设置
`BNB_CUDA_VERSION=124`，不升级系统 glibc、不修改公共 CUDA 安装。此覆盖方式
见 [bitsandbytes 官方说明](https://huggingface.co/docs/bitsandbytes/v0.45.4/installation)。
原模型和微调模型必须使用相同覆盖配置，并由实际量化加载、生成和反向传播验证。

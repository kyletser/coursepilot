## 技术栈没有放进一行的部分，也要会解释

- Redis 在此主要承担 Celery 消息中间件，不声称实现了问答缓存命中优化。
- Celery 管理异步任务；Worker 是执行任务的进程，不是另一个模型。
- Ollama 本地运行默认 `qwen3:4b`；BGE Embedding 和 Reranker 并非由 Ollama 统一运行。
- 微调实验使用 Transformers + PEFT 加载基座与 Adapter，通过兼容 HTTP 接口验证；没有把 Adapter 自动装进默认 Ollama。
- Docker Compose 管理应用与数据库依赖，不意味着完成了生产容灾和高并发部署。
- pgvector 便于复用关系数据与权限事实，不声称在所有规模优于专用向量数据库。

## 一分钟介绍整个项目

CoursePilot 面向高校课程，重点不是让模型自由发挥，而是让回答和学习状态有依据。
问答侧用显式流程管理检索、证据门控和引用；检索采用 Dense、BM25、RRF 和重排，
在两门课程的 200 条冻结用例上提升了 Recall 和 MRR。业务侧把教师审核事实留在
PostgreSQL，通过 Outbox 投影图谱，审核题目作答才能事务化更新掌握度。
另外完成了 Qwen3-4B 的 QLoRA 微调和原模型、two-shot 对照。微调改善了构造缺证据
样本的拒答，但没有全面改善事实选择，所以保留原模型默认配置。

## 两个微调追问故事

1. 第一轮课程回归新增一次“链表常数时间插入前提”误拒答。保留检索与解码条件核对输出，
   第二轮补充长证据、条件句后从基座重训；该例恢复，但不能据此说根因唯一或所有退化解决。
2. 外部原文匹配从 20/50 到 39/50 看似改善很大，逐例检查却发现原模型许多正确转述被扣分。
   保留旧报告，在新资料上冻结短答案字段与缺证据配对再测，得到正例同为 47/50 的结果。
   这说明指标偏好复制风格不能冒充语义准确率提升。

## 写入简历前的复现检查

- 能打开一条训练样本解释问题、证据、目标 JSON 和空 claims；不要只背样本数。
- 能解释 r=16、alpha=32、NF4/BF16、batch 1 × accumulation 8，以及输入 label=-100。
- 输入位置不计损失仍参与前向上下文计算；QLoRA 是参数更新方案，SFT 是训练目标。
- 能用已有 Adapter 比较一条改善和一条退化，说明实验服务与默认部署的区别。
- 运行前检查服务器资源与鉴权；按 [复现入口](../../scripts/finetuning/README.md) 使用新输出目录，禁止覆盖原工件。
- 贡献动词与自己能解释、复现的工作一致；如使用 AI 辅助，不编造全手写或独立排障经历。

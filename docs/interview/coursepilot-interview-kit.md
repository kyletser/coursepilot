## 一句话定位

CoursePilot 是面向高校计算机课程的可信学习 Agent：只基于教师发布资料回答，通过混合检索、Claim-Citation 绑定、审核图谱和可审计掌握度，控制幻觉、跨版本泄漏与学习状态漂移。

## 30 秒介绍

我做的是一个面向高校课程的可信学习 Agent。它只允许依据教师发布资料回答，模型输出结构化 Claim 和服务端分配的引用编号，最终做 Grounding 校验；证据不足就拒答。检索采用 BGE-M3、BM25、RRF 和重排，结果重新经过课程和索引版本校验。两门课程 200 条检索上 Recall@5 从 94.5% 提升到 100%；原问答回归中 40 条不可回答全部拒答，但仍有 3 条可回答误拒答，所以我同时观察拒答和误拒答，不能用一个高分代表全部质量。

## 2 分钟介绍

CoursePilot 围绕可信问答、检索优化、状态治理和模型适配展开。

第一是可信回答。我没有让模型自由选择工具，而是实现显式状态流程：输入检查、五类意图路由、检索、证据门控、最多一次 Query Rewrite、结构化 Claim 生成、Citation 白名单和最终 Grounding。业务数据库决定课程、文档和索引版本，模型只负责组织答案。原 80 条冻结问答中，40 条不可回答问题全部拒答，另有 3 条可回答被保守拒绝。引用评测后来发现会漏计部分错误引用，因此重做了配对计数；新的词法检查仍不能证明全部语义正确。

第二是检索效果和隔离。Dense 能理解语义，但对术语和缩写不稳定；BM25 擅长精确词，却不理解同义表达，所以两路并发后用 RRF 融合，再用 Cross-Encoder 对 8 个候选重排。200 条检索上 Recall@5 从 94.5% 到 100%，MRR@5 从 88.4% 到 98.6%。向量结果不被直接信任，还要通过 PostgreSQL 重新加载，并校验课程、发布状态和活动索引覆盖文档集合，防止旧会话读到新资料。

第三是状态治理。教师审核候选先写 PostgreSQL，Outbox Worker 再幂等投影 Neo4j，避免双写不一致。只有审核题目的有效作答能更新 Beta-Bernoulli 掌握度，QuizAttempt 和 MasteryState 在同一事务中通过幂等键与行锁更新。学习路径只使用审核通过的前置关系。

性能上，本机 BGE 重排是瓶颈。我把候选从 20/20/10 缩到 10/8/5，在相同 40 条问答上总耗时降低 29%，指标不变。外部 CMRC 子集也暴露了边界：Dense 已经 100% 命中时，CPU Reranker 没有增益却慢很多，因此生产上应该按置信度选择性重排，而不是所有请求无条件开启。

模型适配方面，基于 1,448 条 AI 辅助构造样本完成 Qwen3-4B QLoRA SFT，比较原模型、固定 two-shot 和微调模型。在 50 个问题的有/无证据配对输入上，缺证据正确拒答 46/50→50/50，正例字段覆盖均为 47/50。发现事实选择退化后保留默认模型，没有把局部收益包装成全面提升。

## 核心技术取舍

### 为什么不用 LangGraph？

当前难点不是复杂规划，而是证据、权限和状态更新必须可信。显式流程能限制步骤、工具调用和 Query Rewrite 次数，每一步可单测、可审计、可失败关闭。若以后出现跨进程 Checkpoint、复杂分支回放或长任务恢复，再评估 LangGraph；现在引入只会增加状态语义和调试成本。

### 为什么 PostgreSQL + pgvector，而不是 Milvus？

课程、文档版本、权限、测验和掌握度本来就需要关系与事务。规格目标是单课程千到万级 Chunk，当前报告是演示语料，不代表已验证该容量。pgvector 便于复用业务事实进行课程/版本校验，降低部署和一致性成本；不能说它永远优于 Milvus，更大规模需重新评估。

### 为什么还要 Neo4j？

PostgreSQL 是审核事实源，负责事务、权限和审计；Neo4j 是已审核知识图的查询投影，适合多跳前置关系。审核事务只写 PostgreSQL 与 Outbox，Worker 再用 `MERGE` 幂等同步 Neo4j，避免直接双写。

### 为什么用 RRF？

Dense 相似度、BM25 分数的量纲和分布不同，直接加权需要额外标定。RRF 只依赖排名，对异构分数稳定，适合先融合；Cross-Encoder 再对小候选集做更精确判断。

### 为什么本地 Ollama `qwen3:4b`？

它免费、本地可复现、无需 API Key，课程资料不出机器，适合作品集演示。业务层通过 OpenAI-compatible Adapter 隔离供应商。4B 模型的质量和吞吐不能当作生产结论，所以服务端强制结构化输出、引用白名单、Grounding 和失败关闭，并在报告里保留模型版本和硬件。

## 可讲的真实排障故事

### 1. 证据阈值被“排名兜底分”架空

早期代码在缺少可比分数时按排名生成最低 0.56 的兜底分，而 EvidencePolicy 阈值是 0.55，导致普通词法命中也能过门槛。Trace 显示召回本身没有问题，错误发生在检索结果进入 Agent 的归一化边界。我删除排名造分，只接受真实 Reranker 分、0..1 Dense 相似度或 BM25 显式覆盖分；无校准分数时返回 0 并失败关闭。之后把不可回答拒答率和误拒答率放在同一冻结集上观察，而不是单独追求回答率。

追问准备：为什么现在仍是 0.55？正式结果中 40 条不可回答全部拒答，但 40 条可回答有 3 条误拒答，三个正确 Chunk 都排第 1、分数是 0.46/0.47/0.53。现阶段选择保守阈值；下一步用更大开发集做 PR 曲线/阈值校准，不能拿测试集直接调。

### 2. 旧会话串入新发布文档

会话固定了索引版本，但词法回退一度按课程读取全部已发布 Chunk。这样新文档发布后，旧会话可能从词法路线看到新内容，而 Dense 路线仍是旧索引。修复是给 CourseIndex 保存 `covered_document_version_ids`，Dense、Lexical、证据 Hydration 和发布切换统一按覆盖集合；迁移前缺少覆盖清单的索引失败关闭。新索引构建失败时，旧活动索引继续服务。

追问准备：为什么不能信任向量库 metadata？metadata 可能陈旧、被错误写入或绕过业务权限，所以只把命中 ID 当候选，最终以 PostgreSQL 的课程、版本和发布状态为准。

### 3. 评测指标本身有 Bug

学习路径 v2 只有 0.875 合法率。逐案例检查发现 max_depth=1 的路径 `[parent, target]` 被拿去和包含 `grandparent -> parent` 的完整图比较，于是正确路径被误判。修复为只评估 teacher path 范围内的边，v3 为 1.0。这个故事重点不是“算法从 87.5% 优化到 100%”，而是评测标签和被测范围必须一致。

### 4. 正式报告入口在真实运行后崩溃

三基线报告顶层是 `baselines[]`，汇总入口却按单项报告访问 `report["metrics"]`。100 条真实检索已完成后触发 `KeyError`。修复为按 mode 汇总 metrics，并用已生成真实报告做回归验证。此后所有正式运行要求干净工作树、版本化文件名、源数据哈希和禁止覆盖。

## 高频追问提纲

### Grounding 能真正判断语义支持吗？

当前是确定性的词法重叠校验，只能挡住伪造来源、跨课程/版本引用、未知引用编号和明显不支持的 Claim，不能证明深层语义蕴含。冻结评测的引用准确率还使用人工标注 supporting Chunk 做归因，但运行时校验不读取答案标签。生产升级方向是 NLI/交叉编码器支持判断加人工抽检。

### 如何处理 Dense、Lexical 或 Reranker 故障？

Dense 与 Lexical 独立执行；一路失败时保留另一路并在 Trace 标记降级。Reranker 超时保留 RRF 排序。两路都失败时返回 `RETRIEVAL_UNAVAILABLE`，不能让模型自由生成。入库阶段允许 Lexical 可用、Dense 暂时失败的降级状态；模型恢复后用同一文档版本和索引原地重试。

### Outbox 如何处理重复、失败和乱序？

审核事务写业务记录与 Outbox，Neo4j 使用稳定业务键 `MERGE`，失败记录重试次数和错误。设计目标是可重试的最终一致投影，不是全局严格顺序或 exactly-once。既有审计发现关系端点缺失时零写入可能仍被标为成功，以及并发唯一性缺口；不能声称所有重复和乱序场景都已解决。实体版本、端点检查和补偿审计属于需要进一步完善的方向。

### 为什么不让 LLM 更新掌握度？

聊天印象不可复现，也容易被 Prompt 操纵。只有审核题目的有效作答能更新掌握度；Beta-Bernoulli 更新输入是题目、答案、难度和 attempt。幂等键防重复提交，QuizAttempt 与 MasteryState 同事务、行锁更新，每次变化都能审计。

### 外部测试为什么没有证明 Hybrid 更好？

CMRC 固定子集上 Dense 已经 Recall@5/MRR@5 皆为 1.0，Hybrid 无法再提升，CPU 成本反而从约 122ms/题增到 9.03s/题。这证明“混合检索不是无条件开启的银弹”。内部课程术语数据上 Hybrid 有明显增益，生产应按数据分布和 Dense 置信度选择策略。

### 与生产系统还有多远？

已完成远端 GPU 训练与推理、单并发模型及课程回归 P95 测量；仍缺少真实用户流量、跨学科大语料、生产并发压测、完整流式 TTFT、容量规划、在线灰度和长期学习效果实验。当前证明的是可信流程、数据治理和可复现实验，不是大规模线上 SLA。

## 禁止表述清单

- 不说“基于 LangGraph”，当前是自研显式编排。
- 不说“使用 bm25s”，当前是自研轻量 BM25 等价实现。
- 不说“CMRC 官方满分”，外部结果只是 50 问题/200 passage 的自建固定检索子集。
- 不把平均耗时写成 P95，也不声称高并发。
- 不说 KG 在所有课程显著提升；操作系统集上没有增益。
- 不把学习路径 0.875→1.0 描述为算法优化，那是评测范围修复。
- 不使用旧引用准确率 100%；旧计数漏项，修复后的词法指标仍不能证明语义正确。
- 不隐瞒课程可回答误拒答 3/40；历史引用覆盖率 90% 受旧归因口径影响，不当作新指标。
- 不把 `qwen3:4b` 描述为生产模型效果。
- 不声称系统已经过生产流量、亿级向量或线上 SLA 验证。
- 不说 Redis、Neo4j 或 Celery 直接提升了本轮检索分数；它们解决的是异步任务与数据一致性问题。

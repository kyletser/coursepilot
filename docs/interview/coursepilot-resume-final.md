# CoursePilot：可直接使用的简历版本

核对日期：2026-09-11。不使用淘汰的个人简历。微调用于展示真实训练、评估与
部署经验，不声称它必然优于原模型。每条的解释见后附证据映射和追问手册。

## 推荐项目块

**CoursePilot｜可信课程学习 Agent｜核心开发者**

面向高校计算机课程，基于教师发布资料构建带引用问答、审核知识图谱、诊断测验与个性化学习路径，保障课程知识来源和学习状态可追溯。

技术栈：Python / FastAPI / PostgreSQL·pgvector / Redis·Celery / Neo4j / BGE / PyTorch·PEFT / Ollama

- **可信编排与知识边界**：设计显式 Agent 流程，串联意图路由、证据门控、限次 Query Rewrite 和 Claim–Citation 校验；服务端重新验证课程与索引覆盖集，支持证据不足拒答，防止跨课程、跨版本引用。
- **检索优化与对照评测**：实现 BGE-M3 与 BM25 双路召回、RRF 融合及 Cross-Encoder 重排；在两门课程 200 条冻结检索样例上，Recall@5 从 94.5% 提升至 100%，MRR@5 从 88.4% 提升至 98.6%，保留各阶段延迟与降级记录。
- **审核与异步一致性**：以 PostgreSQL 保存审核事实，通过 Outbox 向 Neo4j 幂等投影；测验作答与 Beta-Bernoulli 掌握度同事务更新，使用幂等键与行锁控制重复提交，Celery/Redis 承载入库与评测任务。
- **参数高效微调与模型评估**：基于 PyTorch/PEFT 对 Qwen3-4B 完成 QLoRA SFT，采用 NF4、响应区间 loss mask 和来源分组隔离，以约 0.81% 可训练参数完成 1,448 条样本训练；对比原模型、two-shot 与微调方案，并通过 OpenAI-compatible 接口接入 Agent 验证。

版面不足时，微调条目保留“QLoRA / NF4 / loss mask / 分组隔离 / 三方案对照”，
删去训练样本数；不要为了塞技术名把完整句子压成清单。

## 30 秒：怎么介绍微调这部分？

“我没有把微调当成必然提高准确率的方法，而是针对课程 Agent 的引用格式、条件
保持和缺证据拒答做了 QLoRA 实验。基础权重用 NF4，训练低秩适配器，输入部分
不计算 loss。随后用同精度的原模型、two-shot 和微调模型做对照，发现微调改善
部分拒答行为，但也会选错事实，所以我保留默认模型，并把训练与评测作为可复现
能力交付，而不是只展示一个高分。”

## 2 分钟：完整技术故事

“这个项目首先用 RAG 解决课程资料更新和来源问题，模型只负责根据证据组织答案。
之后我想验证能否通过参数高效训练改善结构化输出和拒答。

我在服务器单张 4090 D 上完成 Qwen3-4B QLoRA，使用 r16 适配器、NF4 和 BF16，
只有响应 JSON 参与监督。资料按来源分组，训练、开发和新测试分开；实际只更新
约 0.81% 参数，并把模型 revision、数据哈希、依赖和适配器哈希记录下来。

第一轮合成测试提高了，但课程回归多了一次误拒答：资料明明说明链表插入要先
定位节点，微调模型却拒答。第二轮补充长证据和条件表达，从基础模型重训，修复
了这次退化。另一个发现是外部原文命中从 20 到 39 看起来提高很多，但逐例看，
原模型多数只是正确转述。所以我没有把它写成准确率，而是在新资料上冻结短答案
字段和缺证据对照。

最后三方案比较显示：正例覆盖原模型和微调都是 47/50；构造缺证据拒答为 46/50
和 50/50；two-shot 在这组反而更容易回答无关证据。模型仍有事实选择错误，
所以结论是训练能改变行为，不保证全面变好。最终通过现有兼容接口验证适配器，
默认模型保留，系统的课程权限、版本和掌握度事务不交给模型决定。”

## 面试时必须守住的边界

- 自研 TrustedAgentCore，不说基于 LangGraph。
- 轻量 BM25 实现，不写 bm25s。
- 已完成的是 QLoRA SFT；全参 SFT、BF16 LoRA、DPO 不是本次已做实验。
- 不写微调准确率 98.8%、外部准确率提升 38 个百分点、零幻觉或大规模线上应用。
- 0.81% 是可训练参数比例，不是推理加速比例；未合并适配器有额外成本。
- 6.64 GB 对应本次固定训练配置，不能承诺所有长度或 batch 都如此。
- 个人面试前需要能自行复跑、定位这些代码；材料本身不等于已经掌握。

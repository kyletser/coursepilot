## SFT、LoRA、QLoRA 的关系

SFT 是使用输入与目标回答进行监督训练；全参数微调、LoRA、QLoRA 描述参数如何更新。
本次是“使用 QLoRA 进行 SFT”，不是在 SFT 与 QLoRA 中二选一。
LoRA 冻结基座、训练低秩增量；QLoRA 进一步量化冻结基座以降低显存开销。
这不证明 QLoRA 在效果上优于全参数微调，也不代表训练计算全部为 4-bit。

第二轮采用 r=16、alpha=32、all-linear、batch 1、梯度累积 8，有效单卡 batch 为 8。
这些是实际采用的折中配置，没有做 rank 8/16/32 的系统消融，不称最优参数。
第二轮峰值 allocated 显存约 6.64 GB；下文第一轮 5.79 GB 是历史训练，不混用。

## 先讲清楚：为什么有 RAG 还要微调？

RAG 解决“去哪里找本课程、这个版本的资料”，微调解决“拿到资料后怎样按约束
回答”。我们没有把不断变化的课程知识全部训练进模型，而是训练引用格式、
条件保持和资料不足时拒答的行为。教师审核、课程权限、活动索引和掌握度事务
仍由程序负责，不能让模型权重代替这些规则。

面试追问：既然提示词也能要求这些行为，为什么一定要训练？

不预设训练一定更好。配对实验给原模型和微调模型相同提示词、证据、精度和
Token 预算，比较额外更新参数是否有收益。原模型本身就是提示词方案基线。
第一轮正是发现了收益和副作用并存，才没有默认推广。

## 本次实际训练了什么？

基础模型是固定 revision 的 Qwen3-4B。冻结基础权重，在线性层加入低秩
增量：`W' = W + (alpha/r) × BA`。本轮 rank=16、alpha=32，数值缩放为 2；
不是把整个模型变成 16 维。只有增量参数参与优化。

QLoRA 的组成要分开解释：

- NF4：基础权重使用 4-bit 量化表示，以减少权重存储。
- Double quantization：进一步量化量化常数，不是连续训练两次。
- BF16：本实验计算精度，不意味着所有张量都按 4-bit 运算。
- LoRA：可训练的低秩增量，是参数高效微调部分。
- Gradient checkpointing：用反向传播时重新计算部分中间结果换取激活显存。

第一轮实际可训练参数为 33,030,144，占含适配器总参数约 0.81%；峰值已分配
显存约 5.79 GB。这是指定批次、长度和代码下的实测值，不是任意上下文长度的
模型显存需求，也不是 `nvidia-smi` 进程总显存或整机内存。

追问：为什么不是全参数微调？

任务主要是输出行为适配，可先用小规模参数更新验证假设。全参数训练的梯度和
优化器状态成本更高；没有做全参数对照，就不能声称 QLoRA 效果更好。

追问：为什么不直接做 DPO？

目前样本是“问题、证据、正确结构化响应”，适合监督微调。DPO 还需要可靠的
偏好对及清楚的优劣标准。不能把两个随机答案凑成偏好数据，也不能把未做的
DPO 写进技术栈。若后续问题是多个合法回答之间的偏好，可另建数据验证。

## 为什么只计算响应区间的 loss？

输入含系统规则、问题和证据；这些 token 的 label 设为 -100，不参与监督损失。
目标 JSON 和结束 token 才是需要模型学习预测的部分。这样避免长证据的复述任务
淹没真正需要学习的回答行为。训练前验证实际编码长度，没有静默截掉答案。

追问：loss 很低不就说明成功了？

不是。结构化模板和重复表达可以让 loss 很低，真实问法和长证据仍可能失败。
第一轮最低开发 loss 的 checkpoint 在短证据合成测试改善，但课程回归多了一次
误拒答。因此必须检查生成结果、分布迁移和端到端行为。

## 数据为什么按资料分组，而不随机打散问题？

同一概念的不同问法很容易共享答案。如果一条问法进入训练、另一条进入测试，
测试可能主要测到答案记忆。分组隔离把同一资料来源放在同一 split。

这仍不是完全独立：我们使用 AI 辅助构造数据，模板风格可能跨 split 相似。
所以还保留原课程回归，并已完成未用于本次训练的公开阅读理解迁移检查。
不能把“来源分组”包装成“人工专家盲测”。

第二轮从基础模型重新训练，增加长证据、多事实与条件表达；v1 测试已经被分析，
只能称开发中观察过的回归材料。v2 新测试在候选固定后执行，不用结果反选
checkpoint，更不删掉不利案例。

## 如何判断不是模型瞎编了引用？

模型输出 Claim 和引用编号，服务端验证编号、Chunk、课程、版本和原文。
这些检查能阻止越权来源和不合法引用，但词法相似不能证明语义蕴含。例如
“允许”与“不允许”可能高度重叠却含义相反。

因此报告把文本匹配称为代理指标，不称“幻觉率”。同时保存原始生成和经过
TrustedAgentCore 的响应：如果系统改为展示证据摘要，不能记作微调模型成功
生成答案。可回答误拒答和不可回答拒答要分别列分母，不能只汇总一个成功率。

## 一个可以真实讲述的失败故事

问题：第一轮合成测试中，不可回答拒答从 30/40 到 40/40，但真实课程的可回答
误拒答从 3/40 到 4/40。新增失败是链表插入常数时间的前提，原模型能够回答
“已经定位到相邻节点”，微调模型反而拒绝。

定位：保留检索、证据和解码条件，检查同题两模型的输出，确认不是资料突然
不可见。短证据训练上的收益不能保证长证据下仍能识别有效条件。

处理：不修改测试答案，不发布第一轮模型；在训练和开发数据中补充长证据、
多事实与条件保持，第二轮重新训练。课程误拒答回到与原模型相同的 3/40；
新外部对照仍有两条选错事实的退化，因此保留原模型默认配置。

边界：这是实验分布偏差的证据和改进假设；不能说已证明唯一根因或已彻底解决。

## 如何接入现有系统，如何回滚？

实验服务器以 Transformers + PEFT 加载量化基础模型和适配器，通过现有
OpenAI-compatible Adapter 接入 CoursePilot，不改公共问答 API。
远端只监听 loopback，使用鉴权 token 和 SSH 隧道；token 不进 Git。
两个模型别名分别启用或禁用同一适配器，便于同条件对照。

本地 Ollama 演示配置没有被替换。远端实验服务是串行验证端点，没有证明动态
批处理、并发扩展或生产可用性。若切换候选，必须记录模型与适配器哈希，保留
原模型配置；不能仅凭“HTTP 能返回结果”就宣布优化上线。

## 面试时怎样体现广度而不堆名词？

按照问题解释各层：检索用 Dense/BM25/RRF/重排；生成用提示词基线与 QLoRA
对照；可信边界用确定性验证和拒答；实验用数据分组、版本固定与迁移回归；
部署用本地 Ollama 和远端适配器。每一层都讲解决的问题、实际证据与失败边界。

禁止表述：全参数微调、DPO 已完成；语义准确率 98.8%；零幻觉；默认线上模型
已全面提升；只训练 0.81% 参数所以推理必然快；单卡测试等同高并发生产压测。

## 简历数字如何回答追问

1,448 条是第二轮 AI 辅助构造训练样本，不是专家人工标注的真实用户问题。
100 条外部对照是 50 个问题各配有/无证据输入；不属于 100 个独立问题，
也不排除源资料出现在基座预训练中。缺证据正确拒答 46/50→50/50，正例字段
覆盖同为 47/50、误拒答同为 0/50。两条赛事/纪录选择退化说明不宜全面替换。
输入 label=-100 仅屏蔽该位置的监督损失，输入仍参与上下文计算。
